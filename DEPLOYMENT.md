# Deploying Buja Auto Spa ERP (production runbook)

Everything here pairs with the boot guard in `backend/src/config/env.ts`: **in
`NODE_ENV=production` the API refuses to start** with a missing/weak/default
`JWT_SECRET`, a shared access/refresh secret, a missing `DATABASE_URL`, or no
CORS origin. That is deliberate - if it boots, the config passed the checks.

## 1. Server
- Ubuntu 22.04+/Debian 12, 2 GB RAM, Docker + compose plugin.
- DNS: `erp.<domain> → server IP`. Open 80/443.

## 2. Secrets
```bash
git clone <repo> /srv/buja-erp && cd /srv/buja-erp
cp .env.production.example .env.production
./deploy/rotate-secrets.sh        # paste the values into .env.production
```
`JWT_SECRET` and `JWT_REFRESH_SECRET` must be ≥32 chars and different.
Rotating either one signs out every session (by design).

## 3. Database
The compose stack ships **Postgres 16**. Dev stays on SQLite; production uses
`backend/prisma/schema.postgres.prisma` (generated by
`backend/scripts/schema-to-postgres.sh` whenever schema.prisma changes - the
Docker entrypoint swaps it in via `PRISMA_SCHEMA=postgres`).
- Fresh install: `RUN_SEED=0` gives an empty production DB (roles +
  permissions are still seeded? no - seed is all-or-nothing; for
  roles-without-demo-data run `npx tsx src/seed.ts` once inside the api
  container, then rotate every demo password, step 6).
- Migrate from the SQLite data you already have:
```bash
cd backend && npm i -D better-sqlite3
SQLITE_PATH=./dev.db DATABASE_URL="postgresql://buja:PW@localhost:5432/bujaerp" \
  npx tsx src/scripts/import-sqlite.ts
```
`docker compose up -d db` first and expose 5432 temporarily (or run the script
from inside the network with `docker compose exec -T api sh`).

## 4. Launch
```bash
docker compose up -d --build
curl -s localhost/api/health        # via web; or: docker compose exec api wget -qO- localhost:4000/api/health
```
nginx (web container) serves the SPA, proxies `/api` to the API, keeps `sw.js`
uncached and hashes-forever for `/assets/*`.

## 5. TLS
Simplest: put Caddy or certbot+nginx in front of `web:80` and set
`CORS_ORIGIN=https://erp.<domain>`. Or extend `frontend/nginx.conf` with a
443 block and mount certificates into the web container.

## 6. First boot checklist
1. `docker compose logs api | head` - confirm the config passed the guard.
2. Log in as admin, then **rotate every seeded account**:
   `docker compose exec api node -e` … or easier:
   `EMAIL=admin@bujaautospa.bi NEW_PASSWORD='…' npx tsx src/scripts/set-user-password.ts`
   (run for admin, manager, cashier). Old demo passwords stop working and all
   their sessions are revoked in the same step.
3. Settings → Company: set the real company name (location is locked to
   Bujumbura by design).
4. Create real users; grant admin only from Settings → Access & admins.

## 7. Backups & restore
```bash
30 2 * * * cd /srv/buja-erp && ./deploy/backup.sh >> /var/log/buja-backup.log 2>&1
```
14 nightly gzipped `pg_dump`s with sha256 sidecars (restore refuses on
mismatch). **Copy off-box** - `deploy/backups/` dies with the VPS. Restore:
`./deploy/restore.sh deploy/backups/bujaerp-<stamp>.sql.gz` (asks YES; stops
the API for the replay).

## 8. Without Docker
`backend`: `npm ci && npm run build`, then PM2
(`deploy/ecosystem.config.cjs`) or systemd (`deploy/systemd-buja-api.service`)
running `dist/index.js`; `frontend`: `npm run build` and serve `dist/` from
your own nginx with the same two rules (proxy /api, no-cache on sw.js).

## 9. Rate limiting
`/api/auth/*` (except /me, /logout): 20 attempts / 15 min / IP in prod
(`AUTH_RATE_MAX`). Global API: 600 req/min (`GLOBAL_RATE_MAX`). `429` with
`{"code":"RATE_LIMITED"}`. Dev limits are effectively off so QA can run.

## 10. Logging
`JSON_LOGS=1` (prod default in compose): one JSON object per request
(`{ts,level,msg:"http",m,u,s,ms,ip}`) - pipe into journald/loki; logrotate or
`docker compose logs` rotation settings recommended.
